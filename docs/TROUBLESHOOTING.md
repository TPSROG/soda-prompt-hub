# 常见问题与排错

先确认使用模式和安装包日期；软件都显示1.1.0，不能据此判断是不是同一构建。
下载入口见[快速开始](QUICK_START.md)，完整记录模板见[手动验收](acceptance/manual-1.1.0-20260913.md)。

## 页面打不开

1. Windows 单机打开 Soda Prompt Hub；Mac 双机模式打开 Mac 的 Prompt Hub。
2. 看启动器 Core 状态，失败时打开日志；Windows 还可导出诊断 ZIP，分享前检查是否含私密内容。
3. 工作台默认地址是 <http://127.0.0.1:8765/>，ComfyUI 默认8188是另一个服务。
4. 关闭浏览器不是停服。怀疑端口被占用时先确认目标进程，不随意结束未知程序；正常退出旧实例再重试。

源码安装的维护人员可使用 `deploy/mac` 的诊断脚本，但普通 DMG / Setup 用户不需要另找脚本或安装 Python。

## 安装包提示未知发布者或“已损坏”

2026-09-13包没有正式平台签名：Mac 仅有 ad-hoc 签名、没有 Apple 公证，Windows 没有自有 Authenticode 签名。
系统阻止不一定说明文件被篡改，但也不能仅凭“未签名”就忽略告警。

1. 从对应官方 Release 重新核对文件名、大小和 `SHA256SUMS`，不要拿旧构建哈希比较新文件。
2. 哈希不符立即停止安装，重新下载；来源不确定时不运行。
3. 哈希一致但仍被阻止，保留完整提示、系统版本和包名，按系统提供的应用授权流程处理。
4. 没有允许入口、提示恶意软件或仍无法打开时停止并反馈。不要关闭杀毒、Gatekeeper 或修改长期执行策略。

## 软件显示stable，为什么Release是Pre-release

运行时通道来自Python包版本；GitHub Pre-release是这批安装包的验收/发布状态。
本次保持软件1.1.0，但用两个带模式与日期的tag区分验收构建；详见[版本体系](RELEASES.md)。
旧包也可能显示1.1.0，升级需对照Release、hash和对应快捷方式。

## Windows 单机仍离线或要求配对

- 应打开 Soda Prompt Hub，不是独立 Soda Compute Worker；单机无需SMB或另一台设备授权。
- 确认启动器 Core 与本机 Worker 状态，ComfyUI能在同台电脑浏览器打开。
- 在启动器设置确认本机ComfyUI地址。模型服务URL/Key属于AI补全配置，不是ComfyUI配对信息。
- 仍看到Mac配对卡时，核对是否打开了旧服务或另一台设备的WebUI；从正确启动器重新进入。
- 不要通过再开一个独立Worker来修复单机服务，避免使用了另一套配置与任务目录。

## Mac 看不到 Windows 共享目录

1. Windows 开启独立 Worker 所使用目录的共享，日常账号同时需要共享权限与文件夹写权限。
2. Mac“设备连接”按配对引导填写主机和共享名；系统窗口中输入凭据。
3. 也可用Finder“前往 → 连接服务器”，连接 `smb://设备地址/共享名`。
4. 使用Finder实际挂载路径，例如 `/Volumes/PromptHub-Bridge`，不是Windows的 `D:\...` 或ComfyUI目录。

密码交给系统凭据窗口，不写入Prompt Hub。共享恢复后再检查Worker和ComfyUI，不把“目录可访问”当作可计算。

## 设备显示“需要创建任务文件夹”

双机模式：共享已挂载但bridge未准备，按页面操作准备任务目录；不会移动模型文件。
单机模式：本地任务目录由启动器准备；检查启动器错误和目录权限，不去设置SMB共享。

## 共享已连接，但Worker离线

历史自检文件不能证明正在运行。看实时心跳、最后检查时间与ComfyUI状态。
Windows正常启动独立Worker后，等待下一轮心跳刷新；Mac启动器每5秒检查，超过25秒未更新会提示中断。
自检通过仍离线时检查Worker是否只是打开了窗口而未运行、电脑是否休眠，以及两端bridge是否一致。

## Worker 需要更新

区分“建议更新”与协议不兼容：前者可能仍能工作，后者必须先换匹配构建。
任务空闲时正常停服，按[安全升级 Worker](WINDOWS_WORKER.md#安全升级-worker)运行新Setup，
不要直接覆盖运行中的EXE。便携ZIP迁移只用于维护路径。

## 任务一直等待，或有图片却没进项目

- 单机看启动器中的本机Worker；双机看Windows独立Worker，不要求黑色命令窗口。
- 确认ComfyUI可用、任务没有停在失败状态、使用正确的bridge目录。
- 返回的图片还要经过编号、大小与SHA-256校验。在“任务状态”找到待接收结果，按卡片导入。
- 导入后查看当前项目画廊和任务记录；仍不更新时记录任务编号，不手工改数据库或反复投递。

## 更新、扫描或AI补全没有结果

- 先看任务入口的排队/阶段/失败原因；刷新页面或关闭弹窗不等于取消后台任务。
- 资料管理“重建本地索引”读取已有资料，不等于下载仓库更新；下载问题看来源任务中的网络/Git错误。
- AI补全先在“设备连接 → 模型服务”确认URL/Key与模型。返回内容是建议，需要确认应用才写入项目。
- 可选模型没安装时按安装界面引导处理；模型安装在运行WebUI服务的设备，不自动装到远程Worker。
- 取消下载/推理可能需要等待当前操作退出，不反复点击。记录等待时间、任务编号与日志，勿分享Key。

## 数据集冻结失败

按交付前检查处理坏图、来源变化、未审核、缺Caption和格式问题。近似重复提示不等于自动批准。
空间不足时释放运行WebUI服务的那台电脑上的目标磁盘空间。单机交付用本地文件夹或ZIP；
Mac双机模式才有跨设备复制。源图和原始说明不要为了通过检查而覆盖。

## 退出或升级失败

关闭窗口只收起；Mac用“退出并停止服务”，Windows单机用“退出并停止本机服务”。
提示无法安全停服时记录日志，不强杀未知进程，也不继续叠加启动实例。

DMG/Setup覆盖安装不等于自动备份，应先备份个人资料。旧源码更新器才有自己的备份与回滚流程，
详见[Mac维护附录](MAC_GUIDE.md#维护附录旧源码安装与轻量启动器)。
不要删除个人资料目录来修复启动问题；保留旧包，先在隔离位置恢复验证。
