# Prompt Hub 1.1.0 手动验收

这一份用于2026-09-13桌面构建。版本仍是1.1.0，不能只看版本号判断是否新包，请核对Release日期、使用方式与SHA256SUMS。

## 1. 文件在哪、先测哪个

从对应GitHub Release下载附件。建议将两套文件分目录保存为`Mac-Windows`和`Windows-Standalone`，避免混用。

| 使用方式 | 安装文件 | Windows要开哪个程序 |
| --- | --- | --- |
| Windows单机 | `Windows-Standalone\Soda-Prompt-Hub-Desktop-1.1.0-Setup.exe` | 只开Soda Prompt Hub，不另开独立Worker |
| Mac管理Windows | Windows装`Mac-Windows\Soda-Compute-Worker-1.1.0-Setup.exe`；Mac装同目录DMG | 只开Soda Compute Worker；工作台从Mac打开 |

建议先测Windows单机，再退出它，测Mac→Windows。同一轮不要同时开两种Windows启动器，否则容易把设备、任务和结果看串。ComfyUI可以保持运行。

如果旧版独立Worker仍在运行，安装新Worker之前先退出它；安装完成后从新安装器创建的开始菜单/快捷方式启动，不再双击旧便携目录的EXE。

当前构建完成了代码自动化测试和打包校验，但新安装包的完整原生手动验收尚未完成。逐项填写“通过 / 失败 / 未测”。可选模型没安装时标“未测”，不要写“通过”。

## 2. 安装前准备

- [ ] 在软件里备份个人数据，记下现有项目数、一个项目名、模型服务名称与ComfyUI地址。不要在截图中暴露Key。
- [ ] 用启动器提供的退出入口关闭当前Prompt Hub/独立Worker。不要只关浏览器，也不要只点收起窗口。若提示服务无法停止，先记录，别反复启动新实例。
- [ ] 从对应Release下载并运行安装器，正常升级安装；不要混用旧ZIP里的便携EXE。若安装器提示程序仍在运行，先解决再继续。
- [ ] 未正式签名的安装包可能有系统安全提示。核对来源与SHA256SUMS；不必关闭杀毒软件或修改长期执行策略。若提示“损坏”或校验不一致，停止并截图。
- [ ] ComfyUI本身可以在浏览器正常打开，并能用已配置的工作流出图。准备一个普通测试项目，例如`手动验收-日期`，避免拿正式项目试删改。

首次验收先沿用现有安装位置。把安装包放D盘不会自动迁移已经安装的程序、AppData配置或资料库；要迁移时另行处理，不要手动拖走程序文件夹。

## 3. Windows单机：先走最短闭环

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| W1 启动 | 打开Soda Prompt Hub，观察启动器后打开工作台 | 窗口可拖动/点击，不白屏、不假死；启动中有状态，成功后能进入WebUI |
| W2 本机连接 | 启动器设置填本机ComfyUI地址；WebUI打开“设备连接” | 明确为Windows单机/本机服务，不要求配对Mac或填写共享账号；Worker在线、ComfyUI可用，失败时有可理解原因 |
| W3 AI补全 | “设备连接→模型服务”确认URL/Key及模型；测试项目留几个空白项，点“AI补全”补全空白 | 点击后有进行中反馈，成功后出现可检查的建议；只有确认应用后才写入项目。失败要显示原因，不能悄无声息。会消耗你配置的API额度 |
| W4 出图 | 选择现有工作流、模型和提示词，发送一张图 | 任务有等待/运行/成功或失败状态；成功结果能导入当前项目，画廊与任务数量更新，不需要重启软件 |
| W5 保存 | 改测试项目一处文字并保存，刷新页面 | 文字与图片结果都保留，不出现“保存文字后刚导入图片消失” |
| W6 退出重开 | 从启动器退出并停止本机服务，再启动 | 能正常退出，不留下关不掉的窗口；重开后项目、结果和配置保留，没有重复Worker或端口占用 |

W1–W6都通过，才能说“Windows单机核心流程通过”。首次启动等待多久受机器环境影响；若几分钟仍毫无状态变化，记录时间和日志，不要直接算通过。

## 4. 两种模式都要看的功能清单

可以在单机先完整测一次；Mac→Windows模式再测与跨设备有关的项。一次只启动一个重任务。

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| 模型清单 | 在设备连接分别更新LoRA、底模清单 | 立即有运行状态/任务入口，完成后数量/列表更新；失败有原因，不一直无反馈 |
| 清单翻译 | 查看一项需要翻译的描述，按现有配置执行 | 能看出待处理/处理中/完成或失败；文本确实返回，不只是按钮变色 |
| 资料管理 | 检查资料库更新；选一个标为“可以安全更新”的资料库更新 | 检查/更新均有反馈；完成后状态刷新。网络或Git失败要明确报错。“重建本地索引”只是重读已有资料，不等于从网上下载更新 |
| 结果文件夹扫描 | 先用3–5张测试图的小文件夹扫描，再试较大的结果目录 | 立即出现任务/进度，刷新页面后仍能找到任务；取消能结束任务且保留已导入图片，源图不被移动或删改 |
| AI服务异常 | 在测试用端点填无效URL测试连接，随后恢复 | 有清楚的失败提示，可重试；Key不被页面、错误详情或日志直接显示。不要故意覆盖唯一正式端点 |
| 可选模型 | 打开“管理可选模型”，任选所需模型安装 | 能选择安装/不安装，看到大小/来源/状态；未安装时对应功能说明缺什么，不静默失败。大模型下载可能很久 |
| 打标/说明 | 对测试图执行已安装的WD14或相应说明模型 | 有进度/失败信息，成功产生内容，可手工编辑保存。只测已实际安装并配置的功能 |
| 数据集审核 | 导入测试图，填Anima与Krea2说明；不再改文字，直接审核通过 | 图片审核状态与两份非空说明的确认状态都更新；空白说明不会被自动确认 |
| 数据集交付 | 选保留图，交付前检查，通过后生成版本；下载ZIP并解压 | 图和caption数量对应；Anima标签/Krea2句子与审核内容一致。单机只有本地打开/下载，不出现跨设备复制；浏览器下载授权由你处理 |
| LoRA项目 | 建测试LoRA项目、选择已审核图、检查缺项、生成交付包 | 不满足条件时明确阻止并说明；满足条件后生成可解压的正确文件，不把未完成审核的图默认为通过 |
| 视觉索引（可选） | 已装视觉模型后建索引；观察、取消、再继续 | 发现文件阶段也有反馈，取消可响应，重建/续建后可查到测试图。不装模型时应明确不可用 |
| 窄屏与动效反馈 | 缩窄窗口，点保存/更新/扫描等按钮 | 文本不挤成竖排，按钮可见可点；状态/禁用/完成反馈清晰，无白底浅黄字看不清的问题 |

## 5. Mac→Windows双设备验收

先完成安装准备，退出Windows单机版。Windows开独立Soda Compute Worker和ComfyUI；Mac开新的Soda Prompt Hub。

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| M1 启动与引导 | Mac启动器打开WebUI，进入“设备连接” | 能看到Mac连接Windows的界面和配对引导；首次按引导配置，已有配对可沿用 |
| M2 配对授权 | 按引导连接Windows共享；在macOS系统窗口登录 | 授权后能检查到共享可访问和Worker心跳；不是只显示“上次自检通过”就当实时在线 |
| M3 断开反馈 | 没有任务运行时正常退出独立Worker，观察Mac；再打开Worker | Mac在心跳过期后显示离线/不可计算，重开后恢复在线；无需刷新或重开Mac应用。不是必须瞬间变色，但不能长期误报在线 |
| M4 模型与出图 | Mac更新一次清单；测试项目发一张真实图并导入 | Windows实际接到任务，Mac能观察任务变化；图片回到正确项目，工作流/生成参数可查看 |
| M5 数据集交付 | Mac整理测试图并生成数据集；如需要，使用界面的跨设备复制 | Mac有复制入口，目标正确；Windows收到的图和caption完整，Mac原文件未丢失 |
| M6 正常退出 | Mac启动器点“退出并停止服务”，再启动 | Mac窗口/服务正常退出，Windows的独立Worker不被无故杀掉；Mac重启后项目与配对记录保留 |

## 6. 怎么反馈问题

不必反复重试。失败一项就记录，其余不受影响的项目可以继续。

复制下面这段发我即可：

```text
模式：Windows单机 / Mac→Windows
失败步骤：例如W3、M4
安装包：文件名和Release链接
操作：我先点了……然后……
预期：……
实际：……
等待时间：约……秒/分钟
截图或任务编号：……
退出重开是否恢复：是 / 否 / 未试
```

能打开窗口不等于验收通过；出过一张图也不代表AI补全、资料更新、扫描、交付都通过。你可以先发W1–W6和M1–M6结果，再补功能清单。未测项直接留空，发现明显卡死、数据丢失或跨项目写错时停止该流程。
