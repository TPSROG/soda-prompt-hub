## WIN-ACC-01：备份入口与 Windows 备份失败

### 用户可见现象

1. 当前 1.1.0 启动器和 WebUI 没有真正可用的普通用户图形化备份入口。
2. 维护命令在 Windows 小型资料库实测也失败：
   - 将临时备份目录重命名为正式目录时出现 `WinError 5`；
   - 失败清理 `payload/database` 时出现 `WinError 32`，提示文件仍被占用。

### 当前判断

图形化入口缺失已经确认。Windows 文件占用的具体根因尚未完成最小复现；SQLite 快照连接或其他文件句柄未及时释放是待验证假设，不能当作已确认结论。

### 期望行为

- 启动器或 WebUI 提供“备份个人资料”。
- 显示目标目录、预计大小、可用空间、进度、校验结果和失败原因。
- Windows、macOS 均能创建完整备份并立即校验。
- 恢复只能写入不存在或为空的新目录，不覆盖正在使用的资料库。

### 修复验收

- 用小型隔离资料库复现红测，再修复 Windows 文件句柄或目录发布问题。
- Windows 实机完成创建、SHA-256 校验、SQLite 完整性检查和隔离恢复。
- 对完整约 7.45 GB 资料库进行用户决定的高成本验收。

### 1.1.1 修复结果

已确认 `sqlite3.Connection` 的 context manager 不会关闭连接；现已显式关闭快照和完整性检查连接。资料管理页新增普通用户备份入口、空间与大小估算、后台进度、取消和完成后自动校验。隔离小库自动测试已通过；Windows 完整资料库仍待新包人工验收。

## WIN-ACC-02：“打开所在文件夹”在 Windows 返回 500

### 复现

1. `数据集 → 05 生成交付版本`。
2. 生成 Anima 或 Krea 2 数据集副本。
3. 在“交付历史”点击“打开所在文件夹”。
4. Windows 弹出“请求失败：500”。ZIP 已成功生成，下载功能不受此错误影响。

### 已确认根因

后端 `_reveal_in_finder()` 无条件执行 macOS 命令：

```text
/usr/bin/open -R <path>
```

Windows 没有 `/usr/bin/open`。进程甚至无法启动，因此错误发生在现有返回码处理之前，成为未处理的 500。现有测试 mock 了 `_reveal_in_finder()`，只证明路由传入了目录，没有执行 Windows 平台分支，所以此前漏检。

### 修复方向

- Windows 使用 `explorer.exe` 打开生成版本目录。
- macOS 继续使用 `/usr/bin/open`。
- 明确区分“目录不存在”“系统文件管理器启动失败”和“不支持的平台”。
- 新增 Windows/macOS 平台分支测试，并保留路径边界检查。

### 1.1.1 修复结果

已改为系统文件管理器分支：Windows 使用 `explorer.exe`、macOS 使用 `/usr/bin/open`、Linux 使用 `xdg-open`；无法启动、超时和返回失败均转换为可读错误，不再裸露 500。

## WIN-ACC-03：“中文对照”含义与实际行为不清

### 当前实际行为

图片详情同时显示：

1. Anima 标准英文标签；
2. Krea 2 正式英文自然语言；
3. Krea 2 视觉模型英文草稿；
4. 中文对照；
5. 修正意见。

其中“翻译成中文对照”目前只读取第 3 项“视觉模型草稿”。草稿为空时，即使正式 Krea 2 说明已有内容，也只显示“草稿是空的，没有可对照的内容”。译文只供人工审核，不会保存为最终 Caption，也不会进入交付版本。

Anima 的中英对照是另一套功能：标签以 `中文（canonical English tag）` 的芯片形式显示。它可能来自内置词典、缓存或按需标签翻译，不使用这一整段“中文对照”文本框。

### 容易产生的误解

- 用户会以为该框能翻译 Anima 或正式 Krea 2 Caption。
- 用户会把 Anima 双语标签芯片误认为这个框的成功结果。
- 页面没有清楚指出译文来源和不参与交付的边界。

### 修复方向

- 改名为“Krea 2 草稿中文翻译（仅供审核）”。
- 明示“翻译上方视觉模型英文草稿；不会进入交付版本”。
- 视觉草稿为空但正式 Krea 2 说明非空时，允许明确选择或自动使用正式说明。
- 保持 Anima 标签的逐标签双语芯片，不与自然语言段落翻译混用。

### 1.1.1 修复结果

界面改名为“Krea 2 中文翻译（仅供审核）”，明确不影响 Anima、不进入交付；优先翻译视觉模型草稿，草稿为空时自动使用正式 Krea 2 英文说明。

## WIN-ACC-04：Windows 出图结果来源不透明且只能累计

### 当前数据来源

“Windows 出图结果”只会显示已经导入 Prompt Hub 回流库的图片，来源有三种：

1. 页面手动导入单张图片；
2. “扫描整个结果文件夹”导入；
3. ComfyUI 任务经 Worker 回传并由 Prompt Hub 接收。

“智能检索 → 建立 / 更新本地索引”不会把电脑上的任意图片导入该页面。它只读取 Prompt Hub 已登记的视觉资料，包括已有的 Windows 出图结果，然后建立 CLIP 向量索引。

### 已确认的验收来源

最近一轮自动化人工辅助验收曾扫描：

```text
D:\PromptHub-Bridge\prompt-hub\full-acceptance-20260913\scan-fixture
```

当前页面还包含 `P01_identity.png`、`P02_original_outfit_flower.png` 等不属于该小型 fixture 的图片，说明历史记录同时包含此前目录扫描或 Worker 回传。仅凭现有卡片无法逐张确认来源，因为 UI 没有显示记录中的 `source_path`。

### 当前存储行为

默认内部回流库：

```text
C:\Users\<用户名>\Documents\Soda Prompt Hub\prompt-library\
  test-results\comfyui-imports\
    index.json
    original\
    thumbnail\
```

已有安装也可能沿用 `Documents\Codex\soda-person\prompt-library`。扫描时图片会复制进内部回流库；源文件不移动、不改名、不删除。

扫描另一个目录属于增补，不是切换或覆盖：

- 已有记录保留；
- 相同 SHA-256 跳过；
- 同名但内容不同的图片作为新记录加入；
- 不自动监控目录，需要用户再次发起扫描；
- Worker 回传结果继续进入同一回流库。

### 缺失的产品能力

- 卡片显示来源类型、来源路径、导入时间和导入批次。
- 按来源、批次、项目和时间筛选。
- 设置“常用结果目录”，下次扫描默认使用该目录，但仍允许临时扫描其他目录。
- 安全移除选中记录或某个扫描批次；明确只删除 Prompt Hub 副本，不删除 ComfyUI 原图。
- 清理前显示占用空间、关联项目和影响范围，并支持取消或可恢复操作。

### 安全边界

在增加正式清理界面前，不手动删除 `original`、`thumbnail` 或单独编辑 `index.json`。三者必须一致；直接删其中一项会留下断裂记录。

### 1.1.1 第一阶段结果

新导入记录会保存来源类型、来源根目录、相对路径和导入批次，页面可按来源筛选，并可记住一个常用结果目录。未关联记录可从页面移出，源文件保持不变，管理副本进入内部回收区；有关联记录会拒绝移出。旧 1.1.0 记录没有完整历史路径时只标为“历史导入”。按批次批量选择、容量统计和普通用户恢复回收区留作后续增强。

## WIN-ACC-05：任务取消后的状态表达

### 已观察现象

- 部分已结束任务在页面中仍短暂显示旧状态，需要刷新或重新进入页面才能更新。
- 取消后的历史记录可能只显示通用失败原因，不能清楚区分“用户主动取消”和“程序失败”。

### 当前判断

这是状态反馈问题，尚未形成稳定的最小复现，不能在本文件中断言具体后端根因。需要分别核对后台任务最终状态、API 返回、前端轮询停止条件和历史卡片文案。

### 修复验收

- 对排队中取消、运行中取消、取消请求过晚三种情况建立回归。
- 页面不刷新也能进入最终状态。
- 历史记录明确显示“已取消”、取消时间和已保留的数据，不显示为普通执行失败。

### 1.1.1 修复结果

活动设备任务在任务页可见时自动轮询，运行中取消会继续刷新到最终状态；取消历史显示取消时间和取消原因。服务重启时发现已请求取消的后台任务，也会把最终消息统一为“已取消”。取消请求过晚仍按真实最终状态返回，不伪造取消成功。
