# Soda Prompt Hub Desktop 产品形态与美术 UI 规格

## 1. 设计结论

三个入口属于同一个产品家族，但不做成完全相同的窗口：

| 产品 | 产品形态 | 视觉情绪 | 核心任务 |
|---|---|---|---|
| `Soda Prompt Hub.app` | Mac 启动台 + 菜单栏常驻 | 安静、精致、轻量 | 启动 Core、打开工作台、恢复错误 |
| `Soda Compute Worker.exe` | Windows 计算控制台 + 系统托盘 | 深色、可靠、设备感 | 配置、检查、启动 Worker 与观察 ComfyUI |
| `Soda Prompt Hub.exe` | Windows 完整版启动台 + 系统托盘 | 编辑部、资料中枢 | 启动 Core、选择本机或远程计算、打开工作台 |

它们共用颜色、字体、状态标签、按钮和动效，但信息密度按职责区分。Worker 不伪装成完整工作台，
完整工作台也不重复 WebUI 的业务页面。

## 2. 美术方向

### 2.1 关键词

- Editorial utility：编辑部工具，而非普通设置面板。
- Field instrument：有仪器铭牌和运行状态，但不过度科幻。
- Paper and signal：纸张底色承载内容，强信号色只用于动作和状态。
- Quiet confidence：不使用大面积蓝紫渐变、玻璃拟态、巨型圆角和无意义插画。

### 2.2 视觉记忆点

统一使用一个“SODA 铭牌”：

- 左上角为 `SODA / PROMPT HUB` 两行字标。
- 字标旁使用砖红色圆点或方形印章，表示当前产品角色。
- 右侧使用 monospace 编号，例如 `DESKTOP / 01`、`COMPUTE / 02`。
- 窗口底部保留一条酸绿色状态轨，形成跨平台识别度。

正式 App icon 后续从该铭牌提炼，不在第一轮用 AI 角色头像或汽水瓶图标，避免和工具定位冲突。

## 3. 设计系统

### 3.1 颜色

| 名称 | 色值 | 使用规则 |
|---|---|---|
| Ink | `#171815` | 文字、深色面板、Worker 主背景 |
| Paper | `#ECE8DC` | 主窗口背景 |
| Paper Deep | `#D8D1BF` | 次级卡片、分区底色 |
| Signal | `#A33822` | 主按钮、停止、错误与重要提醒 |
| Acid | `#D7E455` | Ready、进度、当前选择 |
| Muted | `#5B5A53` | 说明文字 |
| White Ink | `#F4EDDF` | 深色区域正文 |

信号色不平均分布：每个界面只允许一个主要砖红动作，酸绿色只表示“正在工作/可使用”。

### 3.2 字体

- Display：`Iowan Old Style`，用于标题和大号数字。
- UI：`Avenir Next`，用于按钮、说明和设置。
- Status：`SFMono-Regular` / `Cascadia Mono`，用于状态、路径、版本和设备数据。
- 中文回退：`PingFang SC` / `Microsoft YaHei UI`。

不把中文正文强行设置为衬线体；中文标题可由西文衬线字标配合中文无衬线副标题。

### 3.3 形状与空间

- 主卡片圆角：`0–4px`，保持纸张与设备面板的硬朗感。
- 按钮圆角：`0–2px`。
- 边框：`1px`，深色透明度约 `18–28%`。
- 阴影只用于窗口层级，不用于每张卡片。
- 页面采用不对称 5:7 或 4:6 分栏，避免均匀三列 SaaS 卡片。

### 3.4 图标

- 首轮使用线性、单色、16–18px 图标。
- 状态主要依靠文字、颜色和形状，不单独依赖图标。
- 不使用 emoji 作为正式图标。
- 错误图标使用砖红实心方块；Ready 使用酸绿横条，不使用通用绿色圆点堆叠。

## 4. Mac 启动台

### 4.1 产品形态

- 文件：`Soda Prompt Hub.app`
- 初始窗口：约 `680 × 500`，不可无限拉伸。
- 启动位置：屏幕中央偏上。
- Core 就绪后：自动打开 WebUI，并在 2–3 秒后收起窗口。
- 后台状态：菜单栏常驻；二次双击重新显示窗口并打开工作台。
- 用户可以关闭窗口但保持 Core 运行；选择“退出并停止服务”才终止 Core。

### 4.2 首页布局

```text
┌────────────────────────────────────────────────────────┐
│ SODA / PROMPT HUB                         DESKTOP / 01 │
│                                                        │
│ Your local creative archive.                           │
│ 本地创作资料中枢                                       │
│                                                        │
│  CORE SERVICE       LIBRARY             COMPUTE        │
│  READY              READY               OPTIONAL       │
│  127.0.0.1:8765     12,403 items        Windows 5060Ti │
│                                                        │
│  [ 打开工作台 ]                                        │
│                                                        │
│  重新启动   查看日志   数据目录   设置                  │
│________________________________________________________│
│ READY · ALL LOCAL SERVICES AVAILABLE                   │
└────────────────────────────────────────────────────────┘
```

### 4.3 启动状态

启动期间不显示假进度百分比，使用真实步骤：

1. 正在定位安装目录。
2. 正在检查资料库。
3. 正在启动 Core。
4. 正在确认服务身份。
5. 已准备好，正在打开工作台。

每步完成后留下细小时间戳，便于高级用户判断慢在哪里。

### 4.4 错误状态

错误发生时窗口不自动消失。主按钮变为“重试启动”，并提供：

- 查看最近 30 行日志。
- 在 Finder 中打开日志目录。
- 打开诊断说明。
- 退出但保留资料。

## 5. Windows Compute Worker

### 5.1 产品形态

- 文件：`Soda Compute Worker.exe`
- 初始窗口：约 `760 × 540`。
- 主背景使用 Ink 深色，强调它是计算设备控制台。
- Worker 运行后可收起到系统托盘，不保留黑色命令窗口。
- `.bat` 继续保留在 `advanced/` 或维护目录，仅用于排障。

### 5.2 首页布局

```text
┌────────────────────────────────────────────────────────────┐
│ SODA / COMPUTE WORKER                        COMPUTE / 02  │
│                                                            │
│  RTX 5060 Ti                                  READY        │
│  15.8 GB FREE · CUDA · COMFYUI 0.34.0                      │
│                                                            │
│  TRANSPORT            WORKER              COMFYUI          │
│  BRIDGE READY         1.1.0 STABLE        REACHABLE        │
│  D:\...\prompt-hub    protocol v2         127.0.0.1:8188  │
│                                                            │
│  TASK LANE  ━━━━━━━━╸                                      │
│  Waiting for the next verified task                        │
│                                                            │
│  [ 停止 Worker ]       打开日志   配置   自检               │
│____________________________________________________________│
│ RUNNING IN SYSTEM TRAY · LAST CHECK 12:33:13               │
└────────────────────────────────────────────────────────────┘
```

### 5.3 首次配置

首次启动不打开 JSON，改成三步向导：

1. 选择 bridge 目录。
2. 定位 ComfyUI，并检查 `127.0.0.1:8188`。
3. 选择可扫描的 LoRA 和模型目录。

高级配置可以切换到 JSON 查看，但默认表单必须覆盖日常需要。路径输入旁提供“选择文件夹”和实时校验。

### 5.4 运行信息

主界面只显示最重要的数据：

- GPU 名称、可用显存。
- Worker 版本与协议。
- bridge 状态与最近任务。
- ComfyUI 可达性。
- 当前状态：等待、领取、生成、回传、失败。

模型数量等次级信息放入可展开的“设备详情”，避免首页成为监控大屏。

## 6. Windows 完整版启动台

### 6.1 产品形态

- 文件：`Soda Prompt Hub.exe`
- 初始窗口：约 `820 × 560`。
- 与 Mac 同为 Paper 浅色主题，但窗口按钮和路径表达遵循 Windows 习惯。
- Core 与可选 Worker 由同一托盘入口管理。
- 首次启动先选择运行模式，以后可在设置中改变。

### 6.2 首页布局

```text
┌────────────────────────────────────────────────────────────┐
│ SODA / PROMPT HUB                            DESKTOP / 01  │
│                                                            │
│ One machine is enough.                                     │
│ 一台电脑，也是一套完整工作台                               │
│                                                            │
│ ┌─────────────────────────┐  CURRENT MODE                  │
│ │ CORE + LIBRARY          │  LOCAL CREATION                │
│ │ READY                   │  本机 Prompt Hub + ComfyUI     │
│ │ 12,403 items            │                                │
│ └─────────────────────────┘  COMPUTE: RTX 5060 Ti / READY  │
│                                                            │
│ [ 打开工作台 ]                  切换运行模式                │
│                                                            │
│ 重新启动   查看日志   备份资料   设置                       │
│____________________________________________________________│
│ LOCAL MODE · NO SMB REQUIRED                               │
└────────────────────────────────────────────────────────────┘
```

### 6.3 模式选择

使用三张纵向选项，不使用复杂拓扑图：

- 只管理资料：无需 ComfyUI，随后也可连接。
- 使用本机 ComfyUI：自动建立本地 bridge。
- 连接另一台计算设备：引导 SMB 或网络驱动器。

选择结果应当用用户语言描述影响，例如“不会启动 Worker”“不需要共享文件夹”。

## 7. 跨端一致性

### 7.1 必须一致

- 字标、颜色、字体层级、状态词和按钮样式。
- Core/Library/Compute 三类对象及五级状态模型。
- 错误文案结构和日志入口。
- 版本、协议和数据路径的位置。
- `打开工作台` 始终是唯一主操作。

### 7.2 可以不同

- Mac 使用菜单栏，Windows 使用系统托盘。
- Mac 遵循 Finder/权限授权，Windows 使用文件夹选择器和 UAC 说明。
- Worker 使用深色计算主题，完整 Desktop 使用浅色资料主题。
- 窗口控制、快捷键和退出行为遵循平台习惯。

## 8. 动效

- 窗口首次出现：内容按标题、状态卡、主操作三段进入，总时长不超过 `420ms`。
- 启动状态轨：酸绿色从左向右推进，但只根据真实步骤变化。
- Ready：状态条完成后停止，不做持续闪烁。
- Worker 领取任务：任务轨轻微横移，表示传输方向。
- 错误：只让错误边框短促出现一次，不抖动整个窗口。
- 尊重 `prefers-reduced-motion`，关闭所有非必要动画。

## 9. 文案语气

界面文案使用“短句 + 事实 + 下一步”，不使用夸张宣传语。

| 场景 | 推荐 | 避免 |
|---|---|---|
| Core 正常 | 工作台已准备好 | 一切完美！ |
| 无计算设备 | 尚未连接计算设备，不影响资料管理 | 设备连接失败 |
| SMB 断开 | 共享目录未挂载；重新连接后可继续投递 | 未知错误 60 |
| Worker 旧版 | 当前协议兼容，建议稍后升级 | 严重版本错误 |
| ComfyUI 关闭 | Worker 正常，ComfyUI 尚未启动 | 整个设备不可用 |

## 10. 原型评审范围

当前静态原型用于确认：

- 三个产品形态是否容易区分又属于同一品牌。
- 浅色 Desktop 与深色 Worker 的关系是否成立。
- 状态卡、主操作与底部状态轨是否清晰。
- Windows 单机模式是否被表达为一等使用方式。

原型不代表：

- 最终系统原生标题栏。
- 最终 App icon。
- 已经接入真实进程、日志或设置。
- 最终安装包体积和系统权限流程。
